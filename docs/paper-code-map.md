# Paper → Code Map: CleanDIFT: Diffusion Features without Noise

Maps the paper (`cleandift diffusion features without the noise.pdf`, arXiv:2412.03439, CVPR 2025 Oral) onto the official implementation in this repo.

Generated by the `paper-to-code` skill. All `file:line` references are clickable.

---

## 1. Paper summary

- **Problem.** Standard diffusion features (DIFT and successors) require adding noise to an image before extraction, which destroys image information and forces per-task tuning of a noise *timestep* `t`. The paper shows (Fig 3) that even at moderate `t=261`, a substantial fraction of feature variance is explained by the injected noise alone.
- **Method (CleanDIFT).** Fine-tune a *trainable copy* of a pretrained Stable Diffusion U-Net to operate on **clean** images, aligning its internal feature maps to the frozen original model's noisy-image features across many timesteps. Alignment is done with timestep-conditioned projection heads and a negative-cosine-similarity objective (Eq 1).
- **Result.** One forward pass yields **noise-free, timestep-independent** features that beat standard diffusion features on semantic correspondence (SPair-71k), monocular depth (NYUv2), semantic segmentation (Pascal VOC), and classification (ImageNet1k) — without timestep tuning or noise ensembling.
- **Cost.** ~30 min on a single A100, ~400 steps; projection heads add ~45M params (SD2.1) and are **discarded at inference**.
- **Generality.** Drop-in replacement for DIFT features; gains transfer to A Tale of Two Features, Telling Left from Right, and to other backbones (SDXL, SDXL-Turbo, PixArt-α, Flux).

## 5. Unused / dead implementations

- **⚠️ Alternative alignment losses `mse` / `l1`** — `sd_feature_extraction.py:419-422`. Implemented for the Table 3 ablation, but every shipped config omits `alignment_loss`, so the default `"cossim"` (`:245`) is always used. Dead in the released configs (only reachable by hand-editing).
- **⚠️ `FiLMNorm` + `LinearSwish` (non-gated) paths** — `sd_feature_extraction.py:198-217`. Selected only when `norm_type='FiLM'` or `use_gating=False`. The configs pass neither key into `adapter_layer_params` (`configs/*.yaml:36-39`), so `FeedForwardBlockCustom` defaults (`:178`) keep `norm_type='AdaRMS'`, `use_gating=True`. **`FiLMNorm` is never instantiated by the shipped configs** even though the paper calls FiLM the "main configuration."
- **⚠️ `input_pure_noise` branch** — `get_features:452-456`. A sanity-check path (`t==999`, feed pure `eps`); not invoked by `train.py` or the depth prober.
- **⚠️ `use_base_model_features` in depth probe** — `depth.py:108-109,181-182`. The shipped `sd21_depth_prober.yaml:11` sets it `false`, so `base_model_timestep: 199` (`:12`) is never read; the baseline-feature probe path is dormant in the default depth run.
- **⚠️ `interpolate_features` `DINO`/`FULL` modes** — `depth.py:193-197`. Config uses `NONE` (`:13`); the upsampling branches are unused by default.

## 6. Code-only mechanisms (not described — or under-described — in the paper)

- **Learned student timestep (`learn_timestep`).** `sd_feature_extraction.py:324-326`, `t_init=261` (`:248`), enabled in both configs (`:23`). The "clean" student U-Net is fed `torch.ones_like(t) * self.timestep` (`:393`), a single **learnable** scalar initialized to DIFT's `t=261`, not "no timestep input" as §3.2 describes. This is a substantive method detail absent from the paper text.
- **Adapter conditioning pathway.** `FourierFeatures → time_in_proj → MappingNetwork` (`sd_feature_extraction.py:274-277`, used `:400-407`). The paper says heads are "point-wise timestep-conditioned FFNs"; the concrete Fourier-feature + 2-layer mapping-network conditioning stack is an implementation detail. `MappingNetwork` defined in `layers.py:62`.
- **Latent bug in `FiLMNorm.forward`.** `sd_feature_extraction.py:208-209`: `shift = scale.view(B, 1, D)` reuses `scale` instead of `shift`, so the FiLM shift equals the scale. Harmless in shipped runs only because FiLM is never instantiated (see §5), but the code path is broken if anyone enables `norm_type='FiLM'`.
- **Engineering extras:** `torch.compile` on VAE/teacher/student/text-encoder (`ae.py:12`, `sd_feature_extraction.py:294,306,310`), bf16 throughout (`:288`), TF32 + dynamo cache bump (`train.py:106-108`), gradient accumulation (`train.py:50,61`), text-encoder/VAE deletion to save memory (`:315,317`), `use_text_condition` toggle for the App-B distilled-conditioning variant (default `true`).
- **`us11`/`us12` decoder outputs** are computed in the U-Net forward (`min_sd21.py:512`) but intentionally not returned — consistent with "except the two final blocks," just worth noting the taps exist.

## 8. Open questions

1. **Was the released checkpoint trained with FiLM or AdaRMS heads?** Paper's "main config" says FiLM; the shipped config defaults to AdaRMS and FiLM is broken (§6). Which produced `cleandift_sd21_unet.safetensors`?
2. **Learned vs fixed student timestep.** Does `learn_timestep=True` (D3) materially differ from feeding a fixed `t=0`/`t=261`? The paper frames the student as timestep-free; the code learns the timestep. What value does it converge to?
3. **Config lr (1e-5) vs paper (2e-6)** (D1) and unbounded `max_steps` with 2000-step warmup (D4): are the shipped YAMLs the actual training recipe, or illustrative defaults? 400 paper steps < 2000 warmup steps is internally inconsistent.
4. **Segmentation (Pascal VOC linear probe) and classification (ImageNet kNN)** evaluation code (§4.4–4.5) is not in this repo. Is it released elsewhere, or only correspondence (notebook + `geoaware-sc-eval` branch) and depth?
5. **COYO pipeline.** The paper crops and resizes a min-768² COYO subset; `DummyDataset` only resizes arbitrary jpg+json. Is the exact data-prep released anywhere?
6. **`feature_dims` for the two final blocks.** `us11`/`us12` exist but are dropped; confirm this exactly matches Fig 11's "feature maps #0–#10" enumeration for both SD1.5 and SD2.1 channel counts.
